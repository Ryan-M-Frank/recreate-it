# Building the challenge collection

Target: a varied collection of 100 reviewed computational challenges. This is a content roadmap, not an availability count.

The current released catalog is catalog.json. RI-0001 is released; RI-0002 remains an unpublished authoring playtest. The private 100-slot idea inventory is not a set of playable packets and contains spoiler-bearing authoring notes.

Publish in reviewed batches: establish the first three challenges under issue #5, then grow through 10, 25, 50 and 100. Plan broad coverage across data structures, algorithms, information representation, graphs, resource allocation and computer systems. Compare underlying mechanisms privately to avoid counting cosmetic rewrites as fresh challenges.

Each candidate must acquire a complete fixed public contract, examples, a GM evaluation packet, alternative approaches, an opt-in hint ladder, conceptual-overlap review, technical checks and human playtests. Difficulty and timing come from observations. Candidates may be replaced when review shows overlap or defects; provisional outline slots do not reserve official RI identifiers.

Add a reviewed release to the permanent run registry and publish the next catalog snapshot only after its original packet/protocol commit exists. Preserve earlier codes and snapshots. See [the discovery contract](catalog-and-run-codes.md) and [authoring workflow](authoring-challenges.md).

Novelty investigation is optional and controlled by the player. Catalog publication does not require players to pursue novelty claims.
